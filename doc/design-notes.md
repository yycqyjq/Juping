# 界面与播放行为笔记

> 本文是 README 拆出的深度文档，总目录见 [README](../README.md)。

电视界面上每一个「看起来随手」的决定背后都有一次踩坑。这一篇按主题记
「为什么长这样」，正文与不变量清单以 `tools/policy-test/run.sh` 为准。

## 顶部状态条只在「有话说」的时候出现

它原来是一进入播放就常显的 —— 于是看视频时画面上永远压着一条半透明黑带。
现在按状态决定：

| 什么时候                         | 状态条                                       |
| -------------------------------- | -------------------------------------------- |
| 正常播放中                       | **隐藏**（视频就是纯画面）                   |
| 暂停                             | 出现，报「停在哪」                           |
| 出错                             | 出现，报错因                                 |
| 缓冲 / 重连中（`TRANSITIONING`） | 出现，说明画面为什么还没出来                 |
| 等待投屏                         | 隐藏（主面板已经在报信息了，再叠一条就重复） |

为什么不干脆删掉：**暂停和出错的那一刻，屏幕上恰好没有任何别的反馈。**
黑屏卡住时要是连它都没有，电视端就彻底没有出口了 —— 只能去连电脑抓 logcat。
所以它不是装饰，是「只在需要时才出现」的排障出口。

状态条左边那个圆点**会跟着变色**：出错亮红、缓冲 / 重连中亮蓝、其余绿。
它原来是**写死的绿点** —— 而状态条现在恰恰只在出错 / 暂停时出现，
于是会出现「绿点 + 出错：…」这种自己跟自己打架的画面。
三米外先被看见的是颜色而不是那行小字，所以颜色必须说实话
（主面板上那个圆点早就改成这样了，这里当时漏了）。

这里有一个不做就会静默失效的坑，同样钉进了源码级不变量：
**它的可见性必须每个刷新周期重算，不能只写在 `applyMode()` 里。**
暂停与出错是**同一个形态内部**的变化 —— 形态没切换，`applyMode()` 根本不会被走到，
于是「播放中途按暂停，状态条永远不出现」。编译、运行、日志全都正常。

## 进度刷新为什么分两档

| 状态     | 间隔   | 为什么                                                                                                   |
| -------- | ------ | -------------------------------------------------------------------------------------------------------- |
| 等待投屏 | 1500ms | 面板上的信息几乎不变，刷快了纯属浪费（这台设备只有 0.6GB 内存）                                          |
| 播放中   | 500ms  | `01:23 / 03:45` 是用户唯一能对照手机进度条的东西；1.5 秒一跳，拖完总要愣一下才跟上，看起来就像「没同步」 |

播放期间还会**跳过主面板的文字刷新** —— 那几行（设备名 / 地址 / 网卡）在播放过程中
根本不会变，而面板此时本来就是隐藏的。省下的开销正好抵掉提速那部分。

进度显示还有一道**钳制**：位置短暂越过总时长时不显示越界数字（HTTP 流的分段时长
估算是会浮动的）。不钳的话电视上会出现 `10:30 / 03:45` 这种数，看着就像进度「满了」。

## 为什么「音乐播放」必须单独做一层

纯音频流走的是**同一个 `SurfaceView`**，上面什么都没有 —— 电视就是**一片黑**，
只剩一条状态栏。声音明明在放，看着却像投屏坏了。音乐是主要用途之一，
这个误判的代价很高，所以必须换成音符卡片。

这里有两个不做就会前功尽弃的细节，都写进了源码级不变量：

- **音乐层必须画在 `SurfaceView` 之后**。`FrameLayout` 里后画的在上面，
  顺序反了就会被画面层盖住 —— 而画面层此时是全黑的，等于没做。
- **音乐层的背景必须完全不透明**（`@color/bg`，alpha = `FF`）。
  半透明或透明都会让底下那片黑透出来。

三态用**一个整数**而不是两个布尔表示。两个布尔允许出现「既是音频又是视频」
这种非法组合，而它一旦出现，界面会同时显示画面和音符卡片 —— 排查起来非常费劲。

「是不是纯音频」这个判断的权威来源在服务里（`isAudioOnly()`），界面不自己猜：
它由**两个信号合并**得出 —— 控制点传的 DIDL-Lite 里 `upnp:class` 是
`object.item.audioItem` 还是 `object.item.videoItem`，以及 `MediaPlayer` 报的
真实视频尺寸（`getVideoWidth()`）。

> 为什么不用 `getTrackInfo()` 判断有没有视频轨：**那是 API 16 才有的**。
> 而 `getVideoWidth()` 从 API 1 就在，纯音频返回 0 —— 这是 API 15 上唯一可靠的判据。
>
> 元数据只是「提示」，很多控制点根本不传它，所以两个信号都要用；
> `getVideoWidth()` 抛异常时**按「有视频」处理**：宁可退回原来的黑屏，
> 也不要对着一个视频弹出音乐卡片 —— 后者更离谱，也更难解释。

## 音乐界面：歌名放大 + 封面 + 歌手 / 歌词（批 3.6）

音乐卡片原来把**字号层级排反了**：最大最粗的一行是写死的静态标题「音乐投屏」
（34sp），而真正的歌名（`music_source`）被挤在 17sp —— 用户最想看的信息反而最小。
这一版把静态大字删掉，让歌名占据主位（32sp 粗体、主色），并补齐歌手行。

| 行   | 来源                        | 取不到时             |
| ---- | --------------------------- | -------------------- |
| 封面 | `upnp:albumArtURI`          | 退回 `ic_music` 图标 |
| 歌名 | `dc:title`（回退文件名）    | 显示文件名           |
| 歌手 | `upnp:artist`               | 整行 `GONE`          |
| 歌词 | `lyrics` / `dc:description` | 整行 `GONE`          |

**封面**是这一版唯一新增的「网络 + 解码」路径，纪律与图片投屏完全一致：
后台线程下载、`inJustDecodeBounds` + `inSampleSize` 降采样、三字段缓存
（`coverUri` / `coverLoadingUri` / `coverFailedUri`，地址没变不重下、失败地址不每
tick 重试）、换歌时**代次作废**并 `recycle` 旧位图。另加三道封面专属约束：
**流式落盘、上限 16MB**（地址是控制点给的任意 URL，真机实测从 27KB 到 5.5MB 不等；
整份读进内存就是 OOM 入口，所以先落临时文件再解码，见批 3.7）、**连接 5s / 读 15s
超时**、**解码目标按封面框的实际尺寸（220dp）算**（照片是全屏显示、目标 1600px；
封面若复用这个数就是 4 倍过采样，一张 3000×3000 的封面会解出约 9–10MB）。
`albumArtURI` 常见多尺寸（`JPEG_TN` / `SM` / `MED` / `LRG`），按「中 → 大 → 小 →
缩略」择优，不无脑取最大；没有档位信息（裸元素）则退回第一个可用地址。

**三级降级，任何一级都不留白块**：地址为空 → 直接显示 `ic_music` 图标（**不发起
网络请求**）；拉取 / 解码失败 / 超时 → 同样退回图标；加载中 → 仍是图标。
空白块在深色卡片上看着像界面坏了，所以宁可显示图标。

**歌词是机会性的**：DLNA **没有标准歌词字段**，控制点若把歌词塞进
`lyrics` / `dc:description` 等元素就显示，否则整行 `GONE`（不显示 = 现状，零影响）。
**刻意不接任何外部歌词服务** —— 那会把歌名 + 歌手发给第三方，且盒子常无外网，
失败模式是「时有时无」，最难排查。

**音乐层必须继续不透明**（`@color/bg`，alpha = `FF`）：封面画在**不透明**的音乐层
**之上**，即便封面 PNG 自带透明通道，透出的也是音乐层的深色底，而不是底下
`SurfaceView` 的蓝色。这些都有源码级不变量钉着（`@+id/music_cover` /
`@+id/music_artist` / `@+id/music_lyrics` 存在、**歌名字号 ≥ 音乐层内所有其它
TextView**、写死的静态大字已移除、封面 `ImageView` 有默认 `src`、封面在后台线程、
三字段缓存、换图 `recycle`）。

## 换歌不闪待机面板 + 封面改流式落盘（批 3.7）

**一、换歌时不再闪一下待机面板。** 网易云换歌是**先 `Stop` 再 `SetAVTransportURI`**
（真机实测相隔 ≈230ms）。`Stop` 一到，服务立刻清 `currentUri`（这是协议正确性，不能
改）—— 界面这一拍就判成空闲、闪出待机面板；而空闲态的刷新间隔是 1500ms，于是 230ms
的瞬态被放大成 1.5 秒的「先闪面板、再切回」。修法是 UI 侧加 1.5s **宽限**：刚在放
音频时，`Stop` 后 1.5s 内继续保持音乐形态（面板一次都不出现），并**冻结**卡片不重绘
（否则服务里已清空的字段会把卡片刷成空白 —— 从「闪面板」变成「闪空卡片」）。宽限
**只对音频**：视频态 `player.stop()` 后视频层无内容，老 MTK 会输出一屏蓝，对视频宽限
等于把蓝屏多留 1.5s。**遥控器返回键**（用户主动结束）置 `userInitiatedStop` 跳过宽限、
立即回面板。服务层与 `ticker` 一行未动。

**二、封面下载改为「流式落临时文件 → 从文件两遍解码」。** 真机实测同一个控制点送的
封面从 **27KB**（网易云《短发》）到 **5.5MB**（《天龙八部之宿敌》）不等 —— 旧的 4MB
上限把 5.5MB 那张**直接拒了**（回落图标，用户看到「没封面」），而整份读进 `byte[]`
又是 OOM 入口。现在边下边写入 `getCacheDir()` 的临时文件（上限放宽到 16MB，约束从
「内存」变成「磁盘/时间」），再 `inJustDecodeBounds` + `inSampleSize` 从文件两遍解码；
**临时文件在 `finally` 里删**（成功 / 失败 / 超限 / 中断都删）。失败按类别打日志
（下载失败 / 超限 / 解不出尺寸 / 解码失败 / 内存不足，都带 URL）—— 原来超限那条
**完全静默**，电视上没有日志可看，只能靠 logcat。照片路径不动（读本地 `/media/`，
不限大小）。另补一条协议自检：`albumArtURI` **没有 `dlna:profileID` 档位时退回第一个
可用地址**（真机上网易云送的正是这种裸元素，恰恰是这条路径生效）。
